# Memoria Diaria: 2026-04-05

## Resumen de Actividad
Hoy se corrigió un error crítico de lógica en `CombatSystem.ts` relacionado con el uso de métodos como propiedades en condiciones booleanas.

## Decisiones y Soluciones
- **Bug Detectado**: En `cancelSpecial()`, se estaba evaluando `this.isChargingSpecial` (un método) como si fuera un booleano, lo que causaba que la condición `if` siempre fuera verdadera.
- **Solución**: Se eliminó la referencia al método de la condición, dejando `this.stats.combatState === "charging_special"` y `this.activeSpecial` como los únicos validadores necesarios.
- **Refactorización Preventiva**: Se realizó un escaneo del directorio `client/src/game` buscando patrones similares (`if (this.xxx || ...)`), pero no se encontraron más casos de este tipo.
- **Validación**: Se confirmó que `VRHud.ts` utiliza propiedades nulas/indefinidas de forma correcta para sus verificaciones de existencia de controles.
- **Mejora de Calibración**: A petición del usuario, se implementó un sistema de calibración en 2 fases (FASE 1: Preparación, FASE 2: Disparo) en el `VRHud`. Esto permite que el modelo ML aprenda ambos estados de un ataque especial.
- **Reset de Gestos y Usabilidad**: Se añadió un botón de **RESET** por cada poder para borrar su entrenamiento ML individual. Además, se implementó una **cuenta atrás de 5 segundos** antes de cada grabación para permitir al jugador prepararse físicamente.

## Notas para el Futuro
- Al programar en TypeScript, prestar especial atención a los warnings de "always return true/false" en las condiciones, ya que suelen indicar el uso de una función/método sin invocarla.
- Mantener la separación clara entre métodos de consulta (`isSomething()`) y propiedades de estado (`isSomething`). En este caso, `activeSpecial` sirve como el mejor indicador de estado para ataques especiales.
